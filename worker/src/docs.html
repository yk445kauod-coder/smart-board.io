Quickstart

Create an account, make an API key, then generate a lesson. The free plan includes 50 AI turns per day, 30 saved lessons, and one API key.

# 1. Create an account (sets the sb_session cookie)
curl -i -X POST http://localhost:8787/auth/register \\
  -H 'Content-Type: application/json' \\
  -d '{"email":"teacher@example.com","password":"change-me-123","name":"Teacher"}'

# 2. Create an API key (cookie auth)
curl -X POST http://localhost:8787/v1/api-keys \\
  -H 'Content-Type: application/json' \\
  -b 'sb_session=...' \\
  -d '{"name":"CLI"}'
# => {"key":"sb_live_...","apiKey":{...}}

# 3. Generate a lesson
curl -N -X POST http://localhost:8787/v1/chat/stream \\
  -H 'Authorization: Bearer sb_live_...' \\
  -H 'Content-Type: application/json' \\
  -d '{"model":"auto","messages":[{"role":"user","content":"Teach fractions with a pizza example"}],"lang":"en"}'
In local development, Vite proxies /api to the worker on port 8787. In production, point VITE_API_BASE at the worker origin.

Authentication

Two methods are supported:

Browser session
sb_session cookie

HttpOnly, SameSite, created by register/login. Used by the app and the admin console.

Server-to-server
Bearer API key

Authorization: Bearer sb_live_… or x-api-key. Keys are hashed; the raw value is shown once.

GET /auth/me
# => { user, org, plan, subscription }

Lessons

MethodPathPurpose
GET/v1/lessonsList lessons in the active workspace
POST/v1/lessonsSave a validated protocol script
GET/v1/lessons/:idLoad one lesson
PUT/v1/lessons/:idReplace title, language, or script
DELETE/v1/lessons/:idDelete a lesson

A protocol script is a JSON object with title, lang, and steps[]. Each step has ops[] using write, line, rect, ellipse, path, erase, plus extended ops such as table, graph, atlas, and periodic.

Streaming

POST /v1/chat/stream returns Server-Sent Events. The scanner emits each op as soon as its JSON object closes, so the board starts drawing before the model finishes.

EventPayload
meta{requestId, model}
provider{provider, model} when OmniRouter picks a provider
delta{text} raw model chunk
op{op} one validated protocol operation
step{count} completed steps
warning{errors[]} skipped invalid ops
done{requestId, chars, ops, steps}
error{requestId, message}
const res = await fetch('/v1/chat/stream', {
  method: 'POST',

  body: JSON.stringify({ model: 'auto', messages: [{ role: 'user', content: 'Teach photosynthesis' }], lang: 'ar' })
});

MCP server

SmartBoard exposes a Streamable HTTP MCP endpoint at /mcp. Use an API key in the Authorization header.

{
  "mcpServers": {
    "smartboard": {
      "url": "http://localhost:8787/mcp",
      "headers": { "Authorization": "Bearer sb_live_..." }
    }
  }
}
ToolWhat it does
smartboard_healthAPI, D1, user, workspace

smartboard_generate_lessonGenerate a protocol script from a prompt
smartboard_save_lessonSave a validated script
smartboard_list_lessonsList workspace lessons
smartboard_get_lessonLoad a lesson by id
smartboard_usagePlan limits and today's usage
curl -X POST http://localhost:8787/mcp \\
  -H 'Authorization: Bearer sb_live_...' \\
  -H 'Content-Type: application/json' \\
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

OmniRouter

Send "model": "auto" and the router tries providers in plan order. A failure before the first token falls through to the next provider; a failure after streaming starts is surfaced to the client instead of duplicating output.

Manual billing

For Egypt and the Gulf, the product supports manual payment without a payment gateway: InstaPay, cash wallet, or bank transfer after a short call. The team confirms the transfer and issues an activation code.

PlanPriceSeatsAI turns / day
FreeEGP 0150
ProEGP 299 / month1500
SchoolEGP 1,499 / month252,000
EnterpriseContactCustomCustom

1. Submit a payment request

curl -X POST http://localhost:8787/v1/billing/manual-request \\
  -H 'Authorization: Bearer sb_live_...' \\
  -H 'Content-Type: application/json' \\
  -d '{"plan":"pro","method":"instapay","reference":"INV-12345","note":"Paid 299 EGP"}'

2. Team approves

In the platform console → Payments → Approve & issue code. The code is shown once; only its hash is stored.

3. Redeem

curl -X POST http://localhost:8787/v1/billing/redeem \\
  -H 'Authorization: Bearer sb_live_...' \\
  -H 'Content-Type: application/json' \\
  -d '{"code":"SB-XXXX-XXXX-XXXX"}'
Payment instructions are configurable with PAYMENT_INSTAPAY, PAYMENT_WALLET, PAYMENT_BANK, PAYMENT_CONTACT, and PAYMENT_WHATSAPP.

Activation codes

Codes are one-time, hashed, revocable, and expire after a configurable number of days. A code can also be created manually from the console for a school or a partner.

POST /v1/admin/activation-codes
{ "plan":"school", "seats":25, "days":30, "maxUses":1, "note":"Partner pilot" }
# => { "code":"SB-...", "record":{...} }

Admin console

The platform console at /admin is for founders and co-founders. It requires a session whose email is in PLATFORM_ADMIN_EMAILS (or users.is_platform_admin = 1).
