## المرحلة 1 — السبورة والحسابات (فرع `phase-1`)

### 1A. الأساس و CI

- [ ] **P1-FND-01** `pnpm` هو مدير الحزم الوحيد: `pnpm-lock.yaml` محدّث، و`packageManager` في `package.json`.
  - القبول: `pnpm install --frozen-lockfile` ينجح من صفر.
- [ ] **P1-FND-02** TypeScript strict مفعّل على كل الكود الجديد (الواجهة + الـ API + المشترك).
  - القبول: `pnpm typecheck` بلا أخطاء مع `strict: true` و`noUncheckedIndexedAccess`.
- [ ] **P1-FND-03** Tailwind مبنية وقت البناء (لا CDN)، مع tokens العلامة (emerald/cyan، خطوط عربية).
  - القبول: `grep cdn.tailwindcss.com index.html` لا يجد شيئاً؛ البناء ينتج CSS محلي.
- [ ] **P1-FND-04** React Router مع مسارات: `/`, `/login`, `/signup`, `/app`, `/app/projects/:id`, `/app/boards/:id`, `/app/library`, `/legacy`.
  - القبول: كل مسار يفتح مباشرة (deep link) بدون 404، و`/legacy` يعرض التطبيق القديم.
- [ ] **P1-FND-05** `pnpm verify` = lint + typecheck + test + build + e2e، ويفشل عند أي فشل.
  - القبول: الأمر يمر محلياً، ونفسه في GitHub Actions.
- [ ] **P1-FND-06** CI على GitHub Actions: job واحد `verify`، يمنع الدمج عند الفشل.
  - القبول: ملف workflow موجود ويشغّل نفس الخطوات؛ نتيجة آخر run مرفقة في PR.
- [ ] **P1-FND-07** إعدادات أمان أساسية: security headers من الـ Worker، CORS مقيّد، body limit.
  - القبول: اختبار يتحقق من الرؤوس على `/health`.

### 1B. السبورة وكل أدواتها

- [ ] **P1-BRD-01** عقد `BoardCommand` واحد (Zod discriminated union) لكل تغيير: مستخدم/وكيل/أداة.
  - القبول: كل mutation في الكود تمر عبر `applyCommand`؛ لا تعديل مباشر على الحالة من المكونات.
- [ ] **P1-BRD-02** أدوات: قلم، هايلايتر، ممحاة، أشكال (مستطيل/دائرة/خط/سهم/مثلث)، نص، تحديد/تحريك.
  - القبول: اختبار reducer لكل نوع + E2E يرسم كل نوع ويظهر على اللوحة.
- [ ] **P1-BRD-03** ألوان وحجم فرشاة، مع لوحة ألوان عربية RTL.
  - القبول: تغيير اللون يؤثر على الأمر التالي؛ لقطة شاشة.
- [ ] **P1-BRD-04** تنقل: pan (مسافة/أداة يد)، zoom in/out/fit، شبكة اختيارية.
  - القبول: E2E يزوم ويلاحظ تغيّر viewport؛ لا يفقد العناصر.
- [ ] **P1-BRD-05** سبورات متعددة داخل المشروع: إنشاء/تسمية/ترتيب/حذف/تبديل.
  - القبول: إنشاء سبورتين، الرسم في كل واحدة مستقل، التبديل يحفظ.
- [ ] **P1-BRD-06** Undo/Redo على مستوى الأمر، مع حدود (100 خطوة).
  - القبول: اختبار: draw → undo → redo يعيد الحالة حرفياً.
- [ ] **P1-BRD-07** نسخ/تعديل عناصر (بما كتبه الوكيل مستقبلاً): duplicate، edit text، move، delete.
  - القبول: اختبار + E2E.
- [ ] **P1-BRD-08** Sticky notes: إضافة، تحرير نص، سحب، ألوان، حذف، resize.
  - القبول: اختبار + E2E؛ النص العربي RTL داخل الملاحظة.
- [ ] **P1-BRD-09** حفظ تلقائي مع debounce + استرجاع بعد التحديث، وعمل بدون نت (localStorage/IndexedDB).
  - القبول: E2E: ارسم، أعد التحميل، الرسم موجود. اختبار offline: افصل الشبكة، استمر بالرسم، أعد الاتصال، يُزامَن.
- [ ] **P1-BRD-10** منع تداخل النصوص وحسابات هندسية في الكود (لا في الموديل): snap، حدود، ترتيب z-index.
  - القبول: اختبارات geometry.
- [ ] **P1-BRD-11** دعم قلم السبورة (Pointer Events + `pointerType`)، ولمس/فأرة، ومنع التمرير أثناء الرسم.
  - القبول: E2E بلمس/فأرة؛ لا يظهر تمرير الصفحة أثناء الرسم.

### 1C. الحسابات والمؤسسات والأدوار وعزل البيانات

- [ ] **P1-AUTH-01** تسجيل/دخول/خروج بإيميل وكلمة مرور عبر Neon Auth (Managed Better Auth)، بدون Google.
  - القبول: طلب حقيقي على بيئة Neon ينجح، والجلسة تُستعاد بعد reload.
- [ ] **P1-AUTH-02** التحقق من JWT في Hono لكل طلب محمي عبر JWKS، ورفض غير الصالح/المنتهي.

- [ ] **P1-AUTH-03** المؤسسات وأنواعها: مالك المنصة، مدرسة/سنتر، مدرس مستقل، حساب مشترك، طالب.
  - القبول: إنشاء مؤسسة عند التسجيل، وتبديل المؤسسة من الواجهة.
- [ ] **P1-AUTH-04** الأدوار: `owner` / `admin` / `teacher` / `student` مع صلاحيات محددة.
  - القبول: مصفوفة صلاحيات في الكود + اختبارات لكل دور.
- [ ] **P1-AUTH-05** دعوة/إضافة عضو للمؤسسة وتغيير دوره وإزالته (للمالك/الأدمن فقط).
  - القبول: اختبار API + واجهة.
- [ ] **P1-AUTH-06** طبقة استعلام واحدة تفرض `org_id` على كل جدول، وترفض أي استعلام بلا سياق مؤسسة.
  - القبول: اختبار وحدة: استدعاء بلا `orgId` يرمي خطأ.
- [ ] **P1-AUTH-07** RLS مفعّل على جداول التطبيق مع policies على `app.current_org_id`.
  - القبول: اختبار عزل حقيقي: مؤسستان، جلسة A لا ترى صفوف B حتى بـ SQL خام.
- [ ] **P1-AUTH-08** Audit log للعمليات الحساسة (إنشاء/حذف/تغيير دور).
  - القبول: صفوف audit تُكتب وتُقرأ للمالك فقط.
- [ ] **P1-AUTH-09** حذف الحساب والبيانات (self-service) — مسودة أولية.
  - القبول: endpoint + واجهة + اختبار؛ يُنقل للبوابة.
